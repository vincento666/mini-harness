## 6. 这台机器上的坑（别再踩一遍）

- **`MINIHNS_API_KEY` 本机没有**。`DEEPSEEK_API_KEY` 与 `MINIHNS_STRATA_KEY` 只存在于 **User 注册表作用域**，每条命令自己注入、永远不要打印值：`$env:DEEPSEEK_API_KEY = [Environment]::GetEnvironmentVariable("DEEPSEEK_API_KEY","User")`。
- 本地模型层：`http://127.0.0.1:8300/v1`，模型 `qwen3.8-flash-next-iq3_xxs`，pid **21436 不要杀**。scratch 的 serve 用端口 **8321**。`httpx` 必须 `trust_env=False`。
- **`git push` 要代理**：`$env:GIT_SSH_COMMAND = 'ssh -o "ProxyCommand=C:/PROGRA~1/Git/mingw64/bin/connect.exe -H 127.0.0.1:7897 %h %p"'`。git 往 stderr 写，pwsh 会报 exit 1 / `NativeCommandError` **但其实是成功的**——看 `xxx..yyy branch` 那行判断。
- PowerShell 5.1 **没有 `-Encoding utf8NoBOM`**：提交信息用 `write` 工具写成 `.tmp/msgN.txt` 再 `git commit -F`。控制台吃中文 → 让 python / `write` 产出 UTF-8 文件，再用内置 `read` 工具读；搜索用内置 `grep`，不要 `Select-String`。
- 要逐字节的 stdout / stderr 分流时用 `cmd /c "… < in.txt > out.txt 2> err.txt"`，PowerShell 的 `Out-File` 会改编码。
- **venv 的 `minihns.exe` 长 argv 会 access violation**（`--append-system-prompt` 喂 24000 字符 → 退出码 `-1073741819`）。用 `python.exe -m mini_harness.cli.main`。这条本身是未修的已知缺陷。
- 变异测试：**先提交再变异**（runner 会 `git checkout -- <file>`）；runner 解析 `FAILED` 行要用 `line[len("FAILED "):]`；变异一轮只跑一路，串行。
- 帮助文本陷阱：`tests/test_cli_chat.py:85` 的 `_flags()` 会抓所有以 `-` 开头的 token，所以**帮助字符串里不许出现 `--`**。
- mypy strict 里 `str | None` 用 `assert x is not None`，不要用 `or DEFAULT_...` 这种假哨兵。
- `rtk ls` / `rtk tree` / `rtk grep` / `rtk find` 本机不可用；搜索用内置 `grep` 或 `rtk rg`。
- **工作树里这批改动不是我动的，永远不要 `git add`**：`.gitignore`、`docs/tools/*.py`、`docs/tools/diagram_defs_m2_*.py`、`docs/tools/qa_svg.py`、`repowiki/`。`git add` 永远写显式路径。
