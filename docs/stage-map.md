# 八阶段对照（2026-10-26）

基线：`main` = `9b3a5bf`，tag `m1`–`m9`。图源：`9.2 八阶段路线`（事件日志 → 会话与存储 → 最小主循环 → 工具管线 → 预算与计量 → 压缩 → 围栏与审批 → 组合与委派）。

## 接壳前必须补齐（按顺序）

1. **P0 压缩正确性**：合 `fix-post-compaction-budget-reading`；UAT 加一场「溢出一次之后，下一句正常问题能跑完」（不是只判退出码 4）。
2. **H1 宿主会话 API**：常驻多会话 HTTP；装配抽成库；开会话 / 发消息 / 取消 / 审批 / 列会话 / snapshot + `seq`；Bearer token；事件回显。
3. **H2 流式与事件回显**：provider SSE；`model/delta` 是 ephemeral、不落日志；最终 `model/response` 是 durable 真相；断线续读不重复。
4. **M10 工具并发与上下文经济**：并发类别 + barrier + 单条结果预算/spill + `read` 字节上限；E1 量 wall-clock 与 token。
5. **M11 存储与恢复**：`--resume` + 格式迁移 + session index + 折叠缓存。
6. **M14 技能 / 斜杠命令 / 渐进披露**：六级根、清单注入、正文按需、CLI 与 host 同一命令面。壳要 `/skill`，所以它是壳前必需。
7. **MEM1 基础记忆**：项目/用户 `MEMORY.md` + `memory` 工具 + `memory/loaded`；**壳前推荐**，不是硬前置——壳 v1 可以不带记忆先上。
8. **M15a 进程收容**：**无人值守壳的硬前置**；只做有人值守的壳可后置。

**建议但非硬性**：M12 子代理（壳要并行子任务时强烈建议）；M15b 文件写拒绝（引入不可信 skills/MCP 或绑非 loopback 时提前）。

## 可以后置

- **M12/M13 委派与目标**：UI v1 不需要；M12 如果做，强调 `maxActiveSubagents = 8`、`maxDepth = 1`、同批 `subagent` 真并发（见 roadmap 的 M12 行）。
- **M15b 文件写拒绝**：个人本地、有人值守、loopback 时可后置；不可信内容前必须提前。
- **M14a–c 个人助理补齐**：工作区契约 / 上下文经济与计量 / UX 工具；M14 之后、壳前建议，但不是硬前置。
- **MEM2 定时巩固**：手动 `memory consolidate` 跑稳之后再谈定时；不是 DSH 的既有实现。
- **E2 组件接缝**：M 核心与 E1 之后；R3/G 的前置，不是接壳前置；目标是会话级组件替换，不是 HMR。
- **E1 评测**：并行做，但不阻塞里程碑。

## 读这张表时不要误读

- 「①–⑧ 都 ✅」不等于「可以接壳」：图不含宿主/壳边界，也不含斜杠命令、记忆与无人值守；H1/H2/M14/MEM1/M15a 是图外的五格。
- 「M15 没做」不等于「围栏没做」：两轴、边界、CAS、审批、进程树收干净都在；M15a 是进程收容，M15b 是 OS 文件写拒绝。
- 「M12–M14 没做」不等于「组合层没做」：配置组合在 M9；缺的是运行时组合（H1）。
