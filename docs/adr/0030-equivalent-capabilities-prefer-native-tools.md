# 等价能力优先由原生工具提供，不靠临时脚本兜底

列目录、搜内容、读文件这类事由 `glob` / `grep` / `read` 这些原生工具承担，工具描述与头部里的平台建议都把它们摆在 `bash` 里的等价命令之前（`ls` / `grep` / `cat`）；一次性脚本是最后手段，不作为产品能力的一部分，也不作为判据的实现手段。理由：原生工具不经 shell，ADR-0009 那条平台语义差异一次都碰不到；而临时脚本多一层运行时依赖——Python 的版本在机器之间不一致，同一个版本在不同平台上的行为也未必一致，拿它当等价能力，结果不稳定、不可复现。

Considered options：只给平台建议、不引导原生工具——否，模型会继续拿 shell 干原生工具能干的事，2026-10-24 的 UAT 就是这么撞上的（`ls` 在 `cmd.exe` 上不存在）；把 `bash` 从工具面拿掉——否，它跑真命令的能力是契约的一部分（ADR-0008）；按平台发不同工具让模型自己挑——否，主流把插件机制用于扩能力面（MCP、skills、hooks），不做 OS 适配，平台适配发生在分发层、执行层与提示层三处（ADR-0029）。

Consequences：`glob` / `grep` / `read` 与 `bash` 的描述各多一句「什么时候用我、什么时候别用我」；这句指引 MUST 与平台无关，平台相关的那半只出现在头部那块里（否则同一句事实有第二个来源，两边早晚分叉）。
