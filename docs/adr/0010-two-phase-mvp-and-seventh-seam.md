# MVP 分两阶段：里程碑从 7 扩到 15，测试缝从六条扩到七条

`docs/dsh-alignment.md` 的走查确认：mini 在**机制流程**上贴合 DSH，在**架构形式**上脱离很大，而缺席的支柱里只有压缩那一根有里程碑。裁决：MVP 分两阶段。**第一阶段**把内核、工件、组合、能力、模型五层的基础打好、围栏有雏形——已完 M1 / M2 / M4 / M3，接下来 M8 运行时语义转向 → M5 窗口预算与压缩 → M9 装配与配置层叠 → M6 REPL → M7 SSE。**第二阶段**把各层补全成**没有 web / Electron 外壳**的完整类 DSH 形态——M10 工具管线加段与执行缝 → M11 投影分流 / 折叠缓存 / resume / 格式迁移 → M12 委派 → M13 目标轮次 → M14 技能与外部触发 → M15 OS 级拦截。**第三阶段**（加壳）等前两阶段做完再规划。测试缝新增第七条：⑦ 委派与目标；组合层与扩展层不新增缝，在 ② 与 ⑥ 判。

Considered options：保持「MVP 到 M7」（否：走查列出的缺席支柱没有一条被排期，九层里委派与扩展两层永远没有落点）；把九层全塞进 M5–M7（否：一个 change 一件事的纪律会散，词表扩张与人手验收的量会失控）；缝保持六条、委派在 ①/⑥ 判（否：子会话日志与父日志的配对关系是一条新的公开边界，塞进回合循环那条缝判不到它）。

Consequences：AGENTS.md 的「MVP 明确不做」八条里六条被覆盖，那节改成阶段边界；词表预计新增 12–18 个值，每个都要配「每个值可达」的判据（Active Lesson 1）；M12 / M13 的判据必须全 mock（CI 不持 API key，ADR-0005），真实形状只能靠人手验收；里程碑编号仍是**决策编号**，执行顺序写在 `docs/roadmap.md`。
