# 闭合是读方派生，不是日志里的记录类型

ADR-0011 在裁决取消语义时顺带写了「被中断的回合由闭合记录收尾」，并在推论里要求词表新增「闭合记录类型」。M8 落地时改判：**闭合不由内核写进日志，而是折叠遇到没有配对结果的 `tool/call` 时派生出来的那条工具结果消息**，结果词是 `TOOL_OUTCOME_UNKNOWN`，它 MUST NOT 出现在任何日志记录里。理由是这样才成立：进程被硬杀时写方没机会写那条记录，而读方每次都要一份配平的上下文——把完整性放在读方，日志才有「任何时刻截下来都能用」这个性质。

Considered options：写方 closer（否：硬杀与崩溃正好在它写之前发生，那条记录在最需要它的场合缺席）；resume 时补进日志（否：M8 没有 resume，那是 M11 的投影分流，且它会把「日志是唯一真源」改成「日志会被事后修补」）；给闭合另立一份词表（否：两份词表描述同一件事，design D6 已否）。

Consequences：ADR-0011 那句「闭合记录类型」不再兑现——内核从不写 closer 记录，词表里也没有这样的事件类型。代价要写清：盘上那份日志在硬杀之后永远半截，「日志是完整事实」只成立于折叠结果，不成立于文件本身；GLOSSARY 里「闭合记录」这一条因此改成以读方为准。M11 要决定是否把派生闭合写回日志（`docs/CURRENT.md` 的 M11 条目）。
