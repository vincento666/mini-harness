# UAT 验收是第五道门禁，tty 那一半不能由 agent 代跑

里程碑的验收判据从两半加严成三半：mock 那一半是四道门禁（测试 / 覆盖率地板 / `mypy --strict` / ruff），真实那一半是接上真实端点把本里程碑的判据跑一遍（ADR-0024），**UAT 那一半是人坐在终端前拿它办一件真事**——不是跑判据，是看用起来是什么样、哪儿别扭。ADR-0005 早就有这条人手验收，但它的位置是「另有一条…它不替代任何一条判据」，实际效果是可选动作：M5 / M6 / M7 的实现、门禁、真实端点判据都绿了，人手那一半还停在「等人跑」，而等人跑的那一半里恰恰装着只有人能判的东西（Ctrl-C 取消一个回合、提示符上的退出、屏幕上那一行长什么样）。本 ADR 把它升成**第五道门禁**：场次与观察表写进 `docs/verification/<change-id>-uat.md`，**那张表没填完，这个 change 不得归档、不得合入 `main`**；前四道门禁不替代它，它也不替代前四道。

## Considered options

- **保持原样（人手验收写进 manual，不作门禁）**：被否。它已经是这个形状，M5 / M6 / M7 的「等人跑」那一半拖了三条里程碑没落地。
- **让 agent 用 ConPTY 或 `WriteConsoleInput` 代跑 tty 场次**：本机 ConPTY 走不通（`UpdateProcThreadAttribute` 恒返回 87，M3 实测），可用的替代形状只能投递按键，判不了「用起来是什么样」。而且这一半的判据本来就是人的观感，代跑等于把判据换成 agent 的自我确认。
- **把 UAT 做成 CI 里的一步**：CI 没有 tty、没有密钥、没有真实工作区，做不成。

## Consequences

- **`tasks.md` 的末尾从三项收尾改成四项**：真实端点验收、**UAT 验收（人跑）**、变异测试一轮、Learning Gate。已同步进 `openspec/config.yaml` 的 `rules.tasks`。
- **UAT 手册在 propose 阶段就立骨架**，不等实现收尾——这样人可以**与实现同步**跑 UAT（本轮的明确要求），也避免「实现完了才想起要设计场次」。
- **归档前如果 UAT 没填完，停下来问人**，不得用「门禁全绿 + 真实端点判据全过」代替它归档。
- **M5 / M6 / M7 补跑**：手册是 `docs/verification/m5-m6-m7-uat.md`（六场：U1 REPL 办真事 / U2 压缩看得见 / U3 溢出退出码 4 / U4 Ctrl-C 取消一个回合 / U5 事件流与断线续读 + Ctrl-C / U6 裸跑默认档位基线）。这份手册填完之前，**M5 / M6 / M7 的 UAT 那一半未过**，上面 ADR-0024 那三份重新验收记录只覆盖真实端点那一半。
- 手册的写法有硬要求：每场一段可直接粘贴的命令、一张观察表、一句「真事是什么」；别扭处必须写清楚，不许只写「正常」。
