# 评测是支撑轨，不是核心能力，也不进完成判据

E1 的评测住在 `scripts/eval/`（runner + 三个最小任务 + 报告），用 mock 与真实端点两种模式量成功率、回合数、工具调用数、token、峰值上下文、压缩/剪枝节省、wall-clock、最大并发、审批次数、首 token 延迟与 `replay` 一致性；产物是 `docs/verification/eval/<date>/report.{md,json}`。它**不进四道门禁、不作为归档条件、不进 CI、不阻塞任何里程碑**：功能对不对由七个 seam 的判据与「mock / 真实 / UAT」三半回答，评测只回答「这一版是不是更快、更省、更稳」。

Considered options：把评测做成第五道门禁——否，指标会随模型与网络漂移，门禁会变成 flaky 的橡皮图章；只靠单元测试——否，单元测试量不到并发收益、上下文节省与真实端点的首 token；接一个公开榜单——否，那不是这个项目的目标，任务集与权重都会绑架设计。

Consequences：评测可以滞后于里程碑，允许「功能绿了、评测没跑」；没有自动回归信号，只能按里程碑或按需跑；真实模式要人跑、要密钥、不进 CI；报告与 README 模板要随 E1 一起立，否则下一个人不知道量什么。
