# 工具结果在产生时立刻落盘；崩溃留下的未配对调用由闭合记录补上

M3 的 design D3 选了「按声明顺序落盘」，代价是结果缓冲到批次结束，硬杀会留下「有调用没结果」的半截前缀，而且没有读方修复（`docs/CURRENT.md` 里唯一带「缺口」标签、没有判据的那一条）。裁决：**以 DSH 为真理转向**——每条结果在产生时立刻落盘，落盘顺序的保证让位于「日志前缀在任何时刻都是完整事实」；崩溃留下的未配对调用在下次读取时由闭合记录补上，带一个「结果未知」的取值，MUST NOT 自动重试。

Considered options：保持缓冲换顺序（否：M5 的压缩与 replay 判据、M11 的 resume 都建在「前缀完整」之上，半截前缀会让它们各自长出一条例外）；立刻落盘但不做读方修复（否：那只是把缺口从可观察变成不可观察）。

Consequences：turn-loop 主规格里「工具调用与结果按声明顺序落盘」这条 Requirement 要在 M8 改；并发只读工具的结果顺序变成**完成顺序**，判据要按集合而不是按序列断言；`TOOL_OUTCOME_UNKNOWN` 进结果词表，配「每个值可达」的判据。
