# 取消是回合级的协作式事件，会话是否终止由入口决定

ADR-0007 把 Ctrl-C 定成「取消整个 session」，代价是取消在 mini 里是**终止**而不是回合内事件，与 DSH 的协作式取消分岔（走查第三节）。裁决：**以 DSH 为真理转向**——内核只有回合级取消：信号换入正在执行的能力，派发前被取消的调用得到一个「派发前被取消」的结果词，派发后被取消的得到「被取消」，被中断的回合由闭合记录收尾。会话是否随之结束由入口决定：一次性 run 在回合闭合后结束会话、退出码 5 保留；M6 的 REPL 与 M7 的端点里会话继续。

Considered options：保持会话级取消（否：它把外壳的策略写进了内核，M6 / M7 要另起一套机制）；取消只闭合当前回合、循环继续（否：一次性 run 里 Ctrl-C 之后还会再调一次模型。当初「Ctrl-C 直接退出」的直觉是对的，但它由**入口策略**兑现，不由内核语义兑现）。

Consequences：`docs/handoff-2026-10-15.md` 决策 15 与 ADR-0007 都成为历史；词表要新增「派发前被取消」这一类结果词与闭合记录类型，每个都要配可达判据；ADR-0002 第 10 条（取消只在回合边界被看到）在 M8 重新打开——它当初是「已处理」，现在改成「被取代」。
