# 验收判据是 mock 与真实两端都通过，mock 只负责单元测试与冒烟

handoff 决策 21「测试默认用 mock、真实只在手动 smoke 里跑」与 ADR-0005「真实那一半归人手验收、不进 CI、不替代上面任何一条判据」合起来的读法把「mock 桩绿」变成了「里程碑完成」；ADR-0022 否掉了这个读法，但只覆盖「依赖模型回复形状的功能」。2026-10-23 人裁决定把它加严并扩到**任何一个功能**：**验收 = mock 那一半（门禁四道全绿）与真实那一半（接上真实端点把该里程碑的判据跑一遍并通过）都通过**——真实那一半不进 CI、不替代门禁那四道，但它不通过就不算完成，mock 全绿不算完成。mock 桩数据的职责是单元测试与冒烟的方便手段，不是验收本身。理由是这个项目最终要接上真实端点给人用，而真实端点给的失败形状 mock 造不出来：没有 `error.code` 只有 `message` 的 400、估算与真 token 的比值随内容变（1.29 至 4 倍）、窗口稍小压缩根本不可能发生。

Considered options：CI 里带密钥跑真实端点（否：CI 不持 API key 是既定选型，真实端点抖动会让门禁不可信）；真实那一半继续只写进 manual（否：那正是 M5 / M6 / M7 三个里程碑一起漏掉的形状——三条真实观察都记进了 `docs/verification/` 却没有一条回灌成判据）；只给模型相关功能加这条（否：窗口预算、围栏、日志重放这些「看起来不依赖模型形状」的功能在真实端点上同样换了一副样子）。

Consequences：**M5 / M6 / M7 按这条重新验收**，真实端点那一半跑完并通过才算数，观察记进 `docs/verification/<change-id>-reacceptance.md`；每个 change 的 `tasks.md` 末尾从此固定三项——真实端点验收、变异测试一轮、Learning Gate；`tests/fixtures/` 存真实产物（ADR-0022）补的是 CI 判据的「形状」那一半，不补「验收」那一半；「等人跑」这一栏从此只剩下的确需要人的动作（终端前的 Ctrl-C、tty 提示符），不再是真实端点那一半。
