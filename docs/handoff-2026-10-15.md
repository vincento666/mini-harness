## 4. 已锁定的决策清单（38 条编号决策 + 6 条不变量，这就是规格输入）

### 4.1 仓库与工具链
1. 独立仓库 `S:\Develop\mini-harness`，独立 git，与 `S:\Develop\agent_harness`（DSH 分析产物）完全隔离。
2. 语言 **Python 3.12**，`requires-python >= 3.12`。
3. 包管理 **uv**；布局 `src/mini_harness/`；**mypy strict**；CLI 框架 **argparse**（零额外依赖）。
4. 包名 `mini_harness`，**命令名 `minihns`**（用户指定）：`minihns run` / `minihns chat` / `minihns replay` / `minihns serve`。
5. 测试 **pytest + pytest-asyncio**。
6. 运行时校验 **pydantic v2**（工具入参、事件 payload、Provider 返回）。
7. 知识文件全建：`GLOSSARY.md`、`docs/adr/`（ADR-0001..0006 = 六条不变量）、`AGENTS.md`（构建/测试命令 + 不变量摘要）。
8. 密钥与配置：`DEEPSEEK_API_KEY` 只从环境变量读；`.env` 进 `.gitignore`；可选 `mini.config.toml`；**日志与事件里绝不写密钥**。

### 4.2 六条不可让步的运行时不变量（照抄 DSH 思想）
- **A 日志是唯一真源**：事件只追加、不改写；「当前上下文」由折叠（fold/projection）派生。
- **B 工具是能力契约**：定义与执行分离；**失败也是结果**（`UNKNOWN_TOOL` / `TOOL_TIMEOUT` / `ABORTED`），不抛异常打断回合。
- **C 回合主循环显式**：记账 → 装配上下文 → 调模型 → 派发工具 → 判定停止。
- **D 上下文有窗口预算与显式溢出错误**（`CONTEXT_WINDOW_EXCEEDED`）。
- **E 能力受围栏约束**：工作区边界 + 写前必读（CAS）+ 「能干什么」与「要不要问人」是两条独立轴。
- **F 全程可观测**：CLI 输出可重放的 JSONL 事件流。

### 4.3 数据层
9. **JSONL 只追加** + `schema_version` 字段；**冷启动全量重放**（无缓存、无检查点）。
10. 事件命名照抄 DSH 的 `${namespace}/${method}` 风格，约 16–20 种：`session/start`、`turn/start`、`context/assembled`、`model/request`、`model/response`、`model/retry`、`tool/call`、`tool/result`、`tool/cancelled`、`compaction/start|summary|end`、`turn/end`、`session/end`、`approval/request|response`、`error/*`。
11. 每次 `run` 一个新 session id，日志 `sessions/<id>.jsonl`；**`--resume` 后置**（与 REPL 一起，MVP 不做恢复）。
12. 折叠产出形状照抄 DSH：**受保护头部**（系统提示 + 工具描述）+ **摘要作为首条 system 消息** + **标记对** + **保留尾部**；原文事件不删，只遮蔽。

### 4.4 能力层（MVP 工具清单）
13. 六个工具：`read` / `write` / `edit`（字面替换 + CAS）/ `glob` / `grep` / `bash`。
14. 并发语义：**只读工具（read/glob/grep）并发，`write`/`edit`/`bash` 串行**，`max_parallel = 8`。
15. 超时与取消：**bash 默认 30s（上限 600s）**、**模型调用 120s**；Ctrl-C 与超时都写 `tool/cancelled` 事件并**继续回合**（不中断）。

### 4.5 围栏层
16. 工作区根 + 路径 allowlist + **写前必读 CAS**。
17. 两轴独立：`--sandbox`（`read-only` / `workspace-write` / `danger-full-access`）与 approval（ask / `--yes`）。
18. headless 的 approval：默认 ask → 往 **stdin** 提问并写 `approval/request|response` 事件；`--yes` 全自动；**非 tty 且未 `--yes` → 围栏拒绝并写事件退出**。
19. **不做 OS 级强制**（Windows ACL / job object / landlock）——推到第二阶段。

### 4.6 模型层
20. **单方法 Provider 接口**：`generate(messages, tools, signal) -> AssistantTurn{content, tool_calls, usage, finish_reason}`。
21. **mock 优先**：JSON fixture 序列（按场景目录）；真实实现走 **DeepSeek 的 OpenAI 兼容端点**。
22. 重试：**只针对 429/5xx 重试一次**，指数退避，写 `model/retry` 事件。
23. 工具调用协议：OpenAI 兼容 `tools`/`tool_calls`，**显式 `parallel_tool_calls = true`**；**非流式**。
24. 窗口默认 **W = 128 000**、输出预留 **O = 8 192**、token 用 **len ÷ 4 启发式**；`--window` / `--reserve` 可覆盖；测试用小 W 强制触发压缩。
25. 系统提示与工具描述：**内置常量，可追加（`--append-system-prompt`）不可替换**。

### 4.7 压缩（用户特别要求进 MVP）
26. 照抄 DSH 公式与机制：触发线 `floor(min(W × 0.8, W − O − 65 536))`、**尾部保留 16%**、语法剪枝、`compaction/start → summary → end` 标记对、原文不删只遮蔽。

### 4.8 CLI 与可观测
27. `minihns run -p "任务"` 一次性 + `--events jsonl`；参数含 `--workspace` / `--model` / `--sandbox` / `--yes` / `--max-turns` / `--window` / `--reserve`。
28. `minihns replay <session-id>` 重放日志、打印折叠后的上下文与回合序列（**进 M1**，验收靠它断言）。
29. 退出码表：**0 成功 / 1 模型或内部错误 / 2 参数错误 / 3 围栏拒绝或审批被拒 / 4 上下文预算溢出 / 5 用户取消**；同时写 `error/*` 事件。
30. `minihns chat`（REPL）与 `minihns serve --http`（SSE 事件流）都要做，见 §5 顺序。

### 4.9 测试
31. **六个预先约定的 seam**（tdd 技能要求先约定再写）：① 回合循环 ② 工具注册与管线 ③ 文件工具契约 ④ 日志追加与折叠 ⑤ Provider 接口 ⑥ CLI 黑盒（subprocess 跑真实命令）。
32. fixture 仓库**只读**：`tests/fixtures/repo`（5 个 `.md` + 一个可跑的小 pytest 工程），每个测试**复制到 tmp 工作区**再跑，永不污染样本。
33. 验收脚本 `scripts/acceptance.py`：固定场景「把 5 个 `.md` 里的 TODO 改成 DONE 并跑测试」，断言 **≥3 次 edit、≥1 次并发工具调用、小 W 强制触发一次压缩、日志可重放得到同一结果、退出码 0**。

### 4.10 流程（SDD + TDD）
34. SDD 用 **OpenSpec**（`openspec/` 目录、change 的 proposal/specs/design/tasks、archive）；执行用 mattpocock 的 `tdd` / `grilling` / `code-review` / `handoff`。
35. **不建独立工单**，只用 change 里的 `tasks.md`。
36. OpenSpec delivery = **skills**；工作流 = 默认 6 个 + **verify-change**。
37. 实现方式：**单代理 TDD 循环为主**（red → green 单切片），只在需要探索时派子代理。
38. git 纪律：**每个 change 一个分支 `change/<id>`**，完成后合入 `main` 并 archive 提交；提交粒度 = 一个红绿循环一次。

### 4.11 明确不做（推到 MVP 之后）
插件容器与热更新、子代理委派与目标状态机、OS 级沙箱、投影缓存与崩溃恢复（`--resume`）、PTC 工具面塌缩、多模型路由与重试策略、web / Electron 外壳实现、独立工单与 triage 标签体系。

## 6. OpenSpec 事实（已核实，可直接照做）

- 包名 `@fission-ai/openspec`；要求 **Node.js ≥ 20.19.0**；`npm install -g @fission-ai/openspec@latest`。
- `openspec init` 生成 `openspec/config.yaml`、`openspec/specs/`、`openspec/changes/`（归档进 `changes/archive/<date>-<name>/`）。
- **官方支持 DeepSeek Harness**：`--tools dsh` → 技能写入仓库根 `.dsh/skills/`，且 `.dsh/skills/` **优先于** `.agents/skills/`；delivery 必须是 `skills` 或 `both`（`commands` 对 DSH 不装任何东西）。
- 默认 6 个工作流：`openspec-explore`、`openspec-propose`、`openspec-apply-change`、`openspec-update-change`、`openspec-sync-specs`、`openspec-archive-change`；可选 `openspec-verify-change`、`openspec-bulk-archive-change`（`openspec config profile` 切换，`openspec update` 刷新）。
- 规格语法是纯 Markdown：`## ADDED Requirements` → `### Requirement: X`（SHALL）→ `#### Scenario:` + **WHEN/THEN**。
- 遥测默认开：`OPENSPEC_TELEMETRY=0` 或 `DO_NOT_TRACK=1` 关闭。
- 来源：[OpenSpec README](https://github.com/Fission-AI/OpenSpec/blob/main/README.md)、[Set up your project](https://openspec.dev/docs/setup)、[Supported tools](https://openspec.dev/docs/supported-tools)。

## 9. 风险与注意事项（下一会话会踩的坑）

1. **OpenSpec 是 Node CLI，产品是 Python**：两者不冲突，但 `openspec/` 与 `.dsh/skills/` 要进 `.gitignore` 之外的版本控制（OpenSpec 官方要求提交这些文件）。
2. **Windows 没有 landlock**：所以 §4.5 的围栏只能靠路径 allowlist + CAS + 令牌式约束，别在规格里承诺「OS 级强制」。
3. **`len ÷ 4` 启发式不是真 token 数**：压缩触发线在真实模型上会偏；规格里要写清「harness 不依据自己的估算做终止决策」，溢出错误只作为兜底。
4. **`edit` 的 CAS 语义**要在规格里写死：读到的内容哈希/原文必须与替换时的原文一致，否则 `STALE_EDIT` 失败结果（不是异常）。
5. **只读并发 + 写串行的调度**是 M3 的核心难点：先写「同一轮内两个 read 并发、两个 edit 串行」的测试，再写实现。
6. **真实模型调用要隔离**：M4 的测试默认仍用 mock，真实调用只在 `scripts/acceptance.py` 的手动 smoke 里跑，密钥缺失时该测试跳过而不是失败。
7. **本会话的模型不支持图像输入**，四份 HTML 文档的图只做了静态结构校验（id/引用/锚点/连通性/对比度），**没有视觉复核**。
8. 拷贝两份 HTML 约 3.2 MB，记得 `.gitattributes` 里标为二进制或至少别在 diff 里刷屏。
