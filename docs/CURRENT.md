## M6 落地的东西（change `m6-chat-repl`，第一个连续会话入口）

- **`minihns chat`**：与 `run` 共用同一份参数表与同一套层叠，只少两个 flag——没有 `-p/--prompt`（人话从 stdin 按行进来），也没有 `--events`。一次 chat 恰一份 session 日志、恰一个 `session_id`；`session/start` 在第一条输入之前写出、`entry` 为 `chat`、`prompt` 是空串；`session/end` 只在会话收尾时写。stdout 上只有不带 `purpose` 的 `model/response` 正文与提示符 `> `。stdin 不是终端也照跑，EOF 即正常收尾（退出码 0）。
- **段（segment）**：一条输入开一个段，`segment/start` / `segment/end` 落进日志（`segment/end` 的 payload 是 `segment_id`、该段最后一个回合的 `stop_reason`、该段实际跑掉的回合数）。一次性 `run` 恰有一个段——内核只有一种循环，入口不另开一条路。词表因此多三个值：`segment/start`、`segment/end`、`user/message`。
- **`max_turns` 是段内上限**，会话级没有上限：段用完 `MAX_TURNS` 回到提示符，下一条输入额度完整；`segment_id` 与 `turn_id` 都在会话内连续编号、不跨段重置。照 DSH：它的交互循环对 `turn` 与 `step` 都不设轮数上限，带轮数上限的只有委派工具的 `maxRounds`（默认 256 → `budget-limited`），那是 seam ⑦ / M15 的事。
- **两级取消**：段在跑时 Ctrl-C → 取消该段（`error/abort` + `turn/end(ABORTED)` + `segment/end(ABORTED)`）、会话回提示符；提示符上 Ctrl-C → 与 EOF 同一条路，`session/end(MODEL_COMPLETED)`、退出码 0。
- **溢出降到回合级**（ADR-0019）：`CONTEXT_WINDOW_EXCEEDED` 只结束该回合。一次性 run 据此写 `session/end` 与退出码 4；chat 里它是段级收尾、会话继续。provider 报出的上下文超限现在先做一次**请求级压缩**并重试一次（上限 1 次，照 DSH 的 `maxOverflowRetries` 默认 1），重试之前补一条 `context/assembled`——日志说的就是实际发出去的那份表层。
- **窗口预算不成立是启动期参数错误**：`window − reserve − 65536 ≤ 0` 时退出码 2、stderr 含 `INVALID_ARGUMENT` 与三个数、不建日志（照 DSH 的 `TargetPressureConfigError` 在配置解析期）。
- **`session/start.payload.entry`**（`run` / `chat`）：记录会话由哪个入口开始（ADR-0020）。

  - **多次压缩的遮蔽范围允许重叠**（实现现状，未裁决）：既有摘要不被遮蔽，新范围可以覆盖旧范围之外的段。规格没有判「两个范围重叠时读方该怎么读」，M11 做投影层时再裁。
  - **CAS 只比「读到的窗口」**：窗口之外的改动不触发 `STALE_EDIT`；取舍与收紧办法记在 `docs/adr/0004-cas-compares-the-read-window.md`。
