# 真端点验收：goal-ux-one-line（一句话任务的 UX）

端点：OpenRouter `qwen/qwen3.8-27b`（`--provider openrouter`），2026-11-26。
**所有提示词都只有一句话，不含任何工具名或流程说明。**

## 迭代过程（重要）

v3 第一版政策写的是「任务**需要多步或多轮完成**时建目标」，结果两场真实任务都被模型判成「一轮能干完」，**没建目标**：

| 会话 | 一句话提示词 | 结果 |
|---|---|---|
| `c7e2ad9f…` | 写个命令行小工具 fizz.py…带一个 pytest 测试 | 未建目标；4 步内写完并跑通，`turn/end=MAX_STEPS` 收尾（既无续跑也无目标） |
| `152fa140…` | 帮我写个贪吃蛇小游戏，能跑起来就行 | 未建目标；一轮写出 `snake.html` |

→ 结论：触发条件不能交给模型「估计工作量」。改成按**任务性质**触发——「要写文件、改代码、跑命令验证或查多处资料」就建目标，并给逃逸口「建完若发现一步能收尾，当轮标 complete」。改后三场全过。
