DSH 复刻实现蓝图

本文件是 DSH运行时架构剖析.html 的增量补充，不替代、不删减原报告。原报告回答「DSH 是什么、为什么这样设计」；本文件回答「人类如何从架构与组件切入，让 AI 把它写出来」。

每张图三件套：渲染图（给人看结构，不读长散文）· 折叠的 IR JSON（给 AI 看的可执行输入，默认折叠不占版面）· 实现契约卡（逐条签名、不变式、错误码、AI 指令卡）。

人类怎么用这份文件

只看渲染图和每图一行的「大白话」。图按 L0→L11 分层，先看 §01 总蓝图建立依赖方向，再按层往下读。不需要读散文。

AI 怎么用这份文件

展开 IR JSON 即得到该图的完整节点/连线/派发语义；契约卡给出必须实现的成员、必须守住的不变式、必须产出的错误码，以及「禁止做什么」和「验收判据」。把某一节的 IR + 契约卡整段喂给编码 agent 即可开工。

01

复刻总蓝图（先看这一层）

三张图给出复刻的依赖方向、里程碑顺序与扩展轴。人类看渲染图，AI 看折叠的 IR 与契约。

02

L0 · 进程与二进制边界

复刻的第一步是把「外壳」和「运行时」拆成两个产物。

03

L1 · 打包与分发结构

两层 asar 的完整性彼此独立，替换外壳不影响运行时。

04

L2 · 组合内核（Cordis）

内核只有四件事：Proxy 上下文、反射服务、Fiber 生命周期、事件派发。这是复刻的地基。

05

L3 · 会话主循环与请求构造

一轮对话如何被拆成事件，事件如何折叠成发给模型的请求。

06

L4 · 工具运行时

工具的行为写在 ToolDefinition 的可选成员里，策略写在 guard / restrict / executionMode 上。

07

L5 · 围栏层

决策类围栏产出策略对象，执行类围栏消费策略对象。

08

L6 · 会话数据层

日志只追加，投影是折叠出来的视图，checkpoint 是恢复的锚点。

09

L7 · 委派、目标与编排

委派、目标、工作流三件事共用同一套 Agent 归属机制。

10

L8 · 模型、凭据与授权

模型调用、凭据解析、交互式授权是三套彼此独立的接缝。

11

L9 · 协议与双面插件

宿主面与客户端面是同一份插件的两副面孔。

12

L10 · 外部触发

定时、命令、Web、终端最终都变成会话事件。

13

L11 · 与典型 harness 的结构差异

三处「把硬编码换成接缝」的地方，就是复刻时的架构验收清单。

每张图一张卡，可直接作为编码任务的输入。列顺序即任务定义：目标 / 输入 → 输出 / 禁止 / 验收判据。

图模块目标输入 → 输出禁止验收判据
01l12-replication-topology先实现 3 个包：kernel（Proxy/Reflect/Fiber/Events）、assembly（EntryTree/Loader/patch）、agent（loop/session/tools）。YAML Entry 列表 + 命令行 patch 覆盖。 → 一个可被 ctx 访问的服务图，和一个能跑一轮对话的 Agent。禁止在 kernel 里出现任何业务词汇（session / tool / model）。把 kernel 单独拿出来，能在无 Agent 的情况下 mount 一个 echo 插件并 dispose 干净。
02l12-replication-milestones每个里程碑产出一个可独立运行的最小产物 + 一条验收命令。上一里程碑的产物。 → 可执行入口 + 契约测试。禁止跨里程碑并行改内核。M2 判据：一条命令行能完成「用户输入 → 模型 → 一次工具调用 → 模型 → 回答」。
03l12-replication-extension-map每轴一个插件包，包内只出现该轴的注册调用。核心暴露的 ctx。 → 可被 patch 开关的 Entry。禁止跨轴互相 import 实现细节。关掉任一轴的 Entry（disabled: true），核心仍能跑通 M2 判据。
04l0-three-process-boundaries复刻时把外壳做成薄壳：只做窗口、IPC 表、preload 暴露三件事。Node 宿主的 stdio 或本地 socket。 → 窗口 + 45 条通道级别的 IPC 契约表。禁止在 main.js 里放业务逻辑。纯 Node（无 Electron）能启动同一 harness 并跑通一轮对话。
05l1-two-layer-asar复刻时保持「外壳产物 + 运行时产物」两个构建目标。同一份源码树。 → 两个可独立升级的产物。禁止把运行时包打进外壳产物。替换外壳产物而不动运行时，harness 行为不变。
06l2-cordis-components实现 4 个文件：context.ts / reflect.ts / fiber.ts / events.ts，总量控制在 2000 行内。插件定义 + 配置。 → 服务图 + 事件总线。禁止用装饰器或元数据注册替代 Proxy 拦截。同一服务键注册两次，后者生效且前者被 dispose；卸载后 ctx 上取不到残留值。
07l2-service-resolution复刻时把 isolate 做成「可见性表」，不是「进程隔离」。Fiber 的 parent 链 + isolate 映射。 → get trap 的可见键集合。禁止用 Symbol 隐藏服务键来替代 isolate 表。两个插件在同一 realm 内互相可见，在两个 realm 内互不可见。
08l2-fiber-state复刻时先写状态机测试，再写实现。插件构造与 dispose 请求。 → 状态转移记录 + 回收记录。禁止在 DISPOSED 之后仍允许注册 disposables。随机顺序注册 10 个 disposer，卸载顺序严格相反。
09l2-patch-layering复刻时把 patch 实现成「列表上的纯函数」，便于单测。Entry 列表 + 多层 patch。 → 新 Entry 列表。禁止在 patch 阶段读取插件实现代码。同一份 patch 连打两次结果不变（幂等）。
10l2-hmr-update复刻时把 volatile 标记做成配置 schema 的一部分。新旧配置。 → 原地提交 或 重启。禁止用文件监听直接触发进程重启。改 volatile 字段时 Fiber 对象引用不变。
11l3-turn-step-sequence复刻时先把事件词表定死，再写循环。用户输入 + 工具定义。 → 事件序列 + 投影。禁止把 UI 状态写进事件。重放事件序列能重建出与在线一致的视图。
12l3-request-derivation复刻时把「折叠」实现成纯函数：同样的事件序列必须产出同样的请求。事件序列 + 投影定义。 → messages + tools 描述 + 请求头。禁止在折叠函数里读时钟或随机数。同一日志重放两次，请求字节完全相同。
13l3-header-cache-decisions复刻时把缓存键做成 (session, checkpoint, keys) 三元组。会话 + checkpoint。 → 快照或 undefined。禁止用文件 mtime 判断缓存有效性。追加事件后 cachedSnapshot 必须返回 undefined 或新快照。
14l4-tool-pipeline复刻时先实现 register + execute + prune 三件事，其余成员全部可选。ToolDefinition + 参数。 → ToolExecutionResult。禁止在 execute 内部直接读 process.env 决定权限。同一工具并发调用时，isConcurrencySafe 为 false 的执行被串行化。
15l4-cancellation-codes复刻时把错误码做成常量表 + 单测断言。AbortSignal + 超时。 → 带码的失败结果。禁止用异常 message 文本承载语义。四种取消场景各自产出各自的码，且都能被投影记录。
16l4-ptc-seam复刻时先实现 resolve（纯策略），再实现 run（受围栏的 spawn）。脚本 + 请求。 → 运行句柄 + 结果。禁止在脚本域暴露 require / import。脚本里尝试访问 fs 得到明确拒绝，而不是静默失败。
17l5-six-fences复刻时把六道围栏写成六个独立插件，各自只暴露自己的接缝。Agent + 会话 + 请求。 → 策略对象或拒绝。禁止在工具实现里内联权限判断。关掉任一围栏插件，其余围栏仍能独立拒绝。
18l5-windows-confine复刻时把常量集中成一张表，实现按表调用。argv + SandboxPolicy。 → ConfinedArgv。禁止用路径字符串前缀比较代替 ACL。工作区外写入被拒，工作区内写入成功，且退出码可预期。
19l5-platform-branch复刻时按 PLATFORM_CHAINS 做能力探测与降级。平台 + 可用工具。 → 选中的链 + ABI 版本。禁止跨平台共用同一份 syscall 拦截假设。探针失败时给出退出码与原因，不静默降级到无围栏。
20l5-approval-sequence复刻时先实现 setPolicy + request 两个方法，overrideOf 后置。Agent + 工具名 + 理由。 → ApprovalOutcome。禁止把审批结果写进工具实现。同一请求在 ask 与 never 两种策略下产出不同结局。
21l5-fs-fence-cas复刻时把观察记录做成 fs 服务内部的一张版本表。读操作 + 写意图。 → FsWriteOutcome 或两个码之一。禁止用 mtime 直接比较作为唯一判据。读 → 外部改动 → 写，必须得到 FS_STALE_VERSION。
22l6-turn-event-skeleton复刻时先写这条骨架的序列化测试。用户输入。 → 事件序列 + 序号。禁止把 UI 状态写进事件。骨架能重放成同一 messages 序列。
23l6-append-checkpoint-barrier复刻时把「追加」和「checkpoint」拆成两个提交点。事件 + header。 → 日志文件 + checkpoint。禁止在追加中途写 checkpoint。崩溃后恢复能重建出崩溃前的视图。
24l6-projection-fold复刻时把投影定义写成 { key, initial, fold(event, state), wire? }。事件流 + 定义表。 → 状态 + 快照。禁止在 fold 里访问外部状态。全量折叠与增量折叠结果一致。
25l6-format-migration复刻时把版本常量与 codec 表放在同一个包里。旧日志。 → 当前版本日志。禁止写跨版本跳跃的迁移。V0 日志经 4 步迁移后与直接写 V4 的结果等价。
26l6-projection-cache复刻时把缓存读写做成两个方法：cachedSnapshot（读）与 write（写）。会话元信息 + 事件。 → 快照或 undefined。禁止把缓存当权威存储。删掉缓存文件后结果与有缓存时一致。
27l6-disk-layout复刻时把 rank 表做成常量数组，扫描顺序即优先级。项目根 + home 目录。 → 技能清单。禁止递归遍历任意深度找 SKILL.md。同名技能在 rank 100 与 500 各一份时，取 100。
28l7-spawn-vs-fork复刻时先实现 start + sendMessage + interrupt 三件事。请求 + 父 Agent。 → 子会话 + 句柄。禁止让子代理直接写父会话日志。子代理结束后父会话能读到其最终结果。
29l7-activation-pool复刻时把 initiator 做成 AsyncLocalStorage 风格的显式包裹。Agent + owner 链。 → 归属判断 + 列表。禁止用全局变量存当前 Agent。withInitiator 内部的异步调用仍能取到正确 initiator。
30l7-goal-state复刻时把轮数计数与阻碍指纹分开存。Agent + 目标 + 轮次。 → GoalView。禁止把「任务很难」写成 blocked 理由。同一阻碍连续 3 轮才产出 blocked，且 blocked_reason 是具体条件。
31l7-workflow-realm复刻时先实现受限脚本域，再实现三个组合子。脚本源码 + args。 → 可 JSON 序列化的返回值。禁止给脚本域注入 require / process / setTimeout。脚本里访问 fs 得到明确拒绝。
32l8-prepare-call复刻时先实现一个假 provider 的 adapter，跑通 prepareCall。配置 + 消息。 → PreparedLlmCall + 流。禁止在 adapter 里读凭据（凭据由 credentials 注入）。换 provider 不改主循环代码。
33l8-credentials-authorization-split复刻时给 credentials 一个内存实现 + 一个测试替身。CredentialRef / CredentialKey。 → ResolvedCredential 或 undefined。禁止把密钥写进配置 Entry。同一 key 并发 begin 只跑一个流程。
34l9-host-client-handshake复刻时先实现 admit + fetch handler，再谈 UI。连接请求。 → PeerAdmission。禁止在客户端侧做权限判定。未授权请求得到结构化拒绝而不是 500。
35l9-remote-wire复刻时把命名空间表做成常量，注册即拼名。宿主服务成员 + @Remote 标记。 → 客户端可调用的方法表。禁止手写客户端 RPC 表。宿主新增一个 @Remote 方法，客户端无需改代码即可调用。
36l9-dual-face-plugin复刻时只写宿主面，客户端面由注册信息自动生成。插件定义。 → 服务 + 客户端方法表。禁止手写两份 API。删除客户端面代码，宿主行为不变。
37l10-external-triggers复刻时给每个触发源一个「转事件」适配器。定时器 / 命令行 / HTTP。 → 会话事件。禁止触发源直接调用模型。定时触发的会话在日志里与人工触发同构。
38l11-dsh-vs-typical-harness复刻时以这三条作为架构验收清单。任一行为变更需求。 → 一个 Entry 或一个注册调用。禁止在核心包里出现 if (toolName === ...) 形式的分支。新增一种工具策略不需要改工具包。

复刻依赖拓扑与实现顺序

实现顺序 = 依赖顺序。下表按本文件的图序排列，即建议的施工顺序。

三条硬规则

  • 内核层（图 06–10）不得依赖装配层与 Agent 层；依赖方向单向。
  • 会话数据层（图 22–27）先于围栏层（图 17–21）落地：没有可回放的日志，围栏的失败无法被观察与审计。
  • 协议与客户端面（图 34–36）最后做：客户端面必须由已存在的宿主服务派生。

图表生成方法与局限

全部 38 张图由 fireworks-tech-graph 技能渲染（IR v1 契约 · style 3 Blueprint · 统一视觉语言），非手绘、非 Mermaid。

质量门与已跳过的检查

  • 每张图依次通过 validate → render --report → check（XML 合法性、箭头 marker、几何、碰撞、组合质量：0 交叉、每边 ≤ 2 折、节点间距 ≥ 40px、容器内边距 ≥ 20px）。
  • 排版与配色由渲染报告 typography.truncated / palette.ratios 判定，无截断。
  • 视觉人工检查已跳过：当前模型不声明图像输入，无法查看 SVG/PNG 成品。本文件的结论只依赖上述自动质量门。
  • PNG 光栅化按用户要求暂缓，交付形态为 SVG + HTML。

证据边界

  • 签名、常量、事件名、方法数取自 re\verified\dsh\（12,412 条目，manifest 12,411/12,411 匹配）与 re\shell\（618 文件）。
  • re\full\ 存在 8 字节偏移，未作为任何引用来源。
  • 标注 inferred 的内容是复刻建议（里程碑划分、五轴划分、部分时序顺序），不是 DSH 实测结论。
  • 全程静态检视，未执行任何被逆向的 DSH 代码。
  • 方法数口径对齐：本文件一律使用「按服务逐个统计的方法签名数」（91 个服务 / 503 条签名，其中 18 条为 readonly 属性）。早期报告中的 584 是把重载与 @Remote 别名分别计数的结果，两者不矛盾，只是口径不同；引用时请以「服务 + 方法数」的形式给出。
