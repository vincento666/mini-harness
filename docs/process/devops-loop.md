# 研发流程：推进范式与停点

**本文只写规则。** 规则为什么这么定、与哪些方案对照过、哪些一次性决定已经落地，见 `docs/process/devops-loop-rationale.md`——改流程时才读那份。

**范围**：本仓库的 change 流程（propose → apply → 两轴 review → 三半验收 → 归档 → 合入）。

## 0. 统一范式：人只选弹窗，其余自动推进

**默认动作是继续，不是请示。** 在已批准的计划与 change 范围内，agent 一路做到下一个停点；人不再输入「继续」。

### 0.1 五个停点（只弹窗，其余不问）

1. **对齐**：范围、优先级、设计分叉需要人选；
2. **警告**：不可逆、破坏性、安全面、成本显著上升；
3. **复核**：子代理裁决出现 blocker，或两轴结论需要人接受/拒绝；
4. **决策**：merge `main`、UAT 归属、改 AGENTS/ADR/流程；
5. **事故**：证据不足、连续失败、计划外新需求。

**目标验证**：属于停点 1 的弹窗，必须附三样——① 一手资料证据（链接 + 关键原句）；② 因果链（前因 → 机制 → 后果）；③ 反方视角（最可能错在哪）。只给结论或只给选项的弹窗不算对齐。

### 0.2 事故恢复

断电、退出软件、手动中止之后：先核 `git status` / HEAD / 活动 change，对照 `docs/CURRENT.md` 与当周计划，报「恢复到哪、下一步是什么」，然后继续——不重新请示已批过的范围。

### 0.3 验证契约（每个 change 的前置）

写实现之前先写一页验证契约，**人只审这一页**：

- **目标**：一句话，能被非实现者读懂；
- **可观察行为**：3–5 条，每条对应一个 seam；
- **判据**：每条行为至少一个测试/真实端点/CI 证据；
- **坏法清单**：3–5 个「做完但不对」的样子，作为变异种子；
- **不验什么**：明确排除项，防止范围漂移。

判据与目标对不上时先改契约再写代码。**范围纪律（2026-11-18 加）**：规格里不许多出 roadmap、proposal 与一手资料都没有的内容；冒出「这样更有价值」的念头就是越界信号，要么删掉，要么在 proposal 里单列「提案扩展」并按 §1.2 弹窗，**不得静默写成 Requirement**；被一手资料否掉而撤回的，在 design 里留一行原因。

### 0.4 契约的双重复核

契约写错，自动推进只会更快地把错误做完。解法是让契约在写代码前被另一个上下文挑错，在写完后被逐条对照。**复核者必须是与撰写者不共享上下文的子代理**：输入给文件路径，不给叙事。

**第一道：契约与对齐复核（子代理，apply 之前）**

- 输入：目标、契约、对应的 spec / roadmap 段落，以及契约引用到的**一手文件路径**；不给实现叙事。
- 六项检查：① **可追溯**（每条目标都有可观察行为，每条行为都有判据）；② **可证伪**（每条判据都存在一种能失败的方式，禁止同义反复）；③ **坏法覆盖**（至少 3 个「做完但不对」的样子）；④ **范围**（`不验什么` 明确，且没有混入实现细节）；⑤ **可读**（非实现者能读懂目标那一句）；⑥ **对齐**（契约里每个与 DSH 同名的机制，都要指到一手实现的赋值点；指不到就明写「无对照」，不许当成已对齐）。
- 输出：`PASS` 或 `GAPS`（每条 gap 带位置与 severity）。GAPS 先改契约，不进 apply；同一契约最多复核两轮，再不过升级为人裁。
- 对齐：按 `docs/reference/dsh-alignment-checklist.md` 十项逐条对一手资料，结论只用 `aligned / simplified / deferred`；后两者人裁后才记账，产物 `<change-id>-dsh-review.md`。

**第二道：对照门禁（子代理，归档之前）**

- 输入：`git diff main...HEAD` + 契约；逐条映射证据（测试名 / 命令 / 输出）。
- 任一判据没有证据 = 未完成，不许归档；只报影响正确性或既定需求的缺口，不报风格偏好——穷追会导致过度工程。

**第三道：实现后的验证与测试**（已有）：四道门禁、真实端点、UAT、变异。仍出问题就修，或提新 change 迭代——不在一轮里无限返工。

**关键 UAT 不得自动化**：涉及数据丢失/不可逆、权限与安全面、外部副作用（发布/回复/合并）、UX 手感与审美、成本显著上升的场景，必须人坐在终端跑；agent 只能准备场次与观察表，**不得代跑**。到 UAT 时必须在弹窗里标明「关键场次，需人跑」并给出场次编号。

### 0.5 模型能力适配

- 完成由外部判据（测试、CI、真实端点、UAT）确认，判据不足先补判据；人的注意力放在**验收标准与分叉**，同一处连续两次失败升级为停点 5。

### 0.6 默认推进模式（2026-11-17 固定）

1. **顺序**：按 `tasks.md` 从上到下推进，不跳组；设计确需前置时先写清理由，实现仍等前序任务。
2. **切片**：每个切片先写判据（断言日志或外部行为）→ 实现 → 跑门禁 → 勾任务。
3. **弹窗**：只在 §0.1 的五类停点、或确实没把握的模糊处弹；其余连续推进，过程输出即审计依据。
4. **收尾**：全量四道 → 变异一轮 → 两轴子代理复核 → 关键 UAT（人跑或明确授权代跑）→ 归档 → 人批合并。
5. **判据与汇报**：问「删掉实现里哪一行它会红」；每轮只给「数字 + 已知缺口」。
6. **工具入口**：`scripts/gates.sh`（四道 + 覆盖率三步）；`scripts/new-change.sh`、`scripts/check-change.sh`（归档前校验）、`scripts/install-hooks.sh`。
7. **硬兜底**：机械步骤一律脚本化，由 git hook / harness hook / CI 执行，不靠记性。

## 1. 什么时候找人

两件事分开看：**先判要不要找人**（1.1），**再定找到人之后怎么问**（1.2）。

### 1.1 六类升级触发（human-in-the-loop）

平时是 **human-on-the-loop**：在已接受的范围里自己诊断、补红、修技术问题、重跑门禁。出现以下六类才升级到人裁：

1. 值或行为无法从已接受的事实推导；
2. 范围或优先级要变（含超出 proposal 的「非目标」）；
3. 架构、公开契约、数据、权限、安全、成本、外部依赖需要实质决策（含新增事件类型/字段、改 payload）；
4. 不可逆或生产动作需要授权（删文件、改日志语义、改 A–F 不变量、merge `main`、会花钱的批量真实端点、UAT 归属）；
5. 出现高影响事故（连续失败、证据不足、计划外新需求）；
6. 有界、有证据的尝试仍无法推进。

改 AGENTS.md、ADR、流程文档同样按第 3 类处理，由人裁。

### 1.2 弹窗的硬约束

- 格式固定四段：**what**（这是什么）／**why**（为什么现在定）／**how**（选项与代价）／**推荐项**。没有这四段就不许弹。
- **每个检查点最多一次弹窗**，同类问题合并成一次多选，避免疲劳。
- 禁止只给结论、只给代号、或把「我的建议」写成「已经定了」。

## 2. 阶段进入六问（grill-me / grilling）

在 roadmap 的关键阶段进入前，propose 之前先答六问，答案由人给、agent 不得自答：

1. 这个阶段的**非目标**是什么（明确不做）？
2. 验收判据里，哪一条最可能被「做完但不对」地满足？
3. 有没有需要先补的一手调研？
4. 有没有会动现有规格或不变量（A–F）的改动？**旧规则的外延被新机制扩大**也算，按这个口径答。
5. 本轮**预授权**的简化/欠账范围是什么？
6. 范围上限：几个切片、什么条件下停？

产出写进 proposal 的「人裁决」小节。六问只问一次，不反复 grill。

**grill 入口**：技能已装（实体在 `~/.agents/skills`，各 harness 链接引用）。`grill-me` 是斜杠入口（只由人触发），模型侧对应 `grilling`。两者都只是**提问器**，产出必须落成上面六问的答案，不能替代人裁决。

## 3. 出口物与播报

### 3.1 Gate Report（每个 change 一份）

`docs/verification/<id>-report.md` 只做索引、不复述细节：

- 四道门禁：命令 + 实测数字（passed / skipped / 覆盖 TOTAL / ruff / mypy）；
- 三半验收：mock / 真实端点 / UAT 各自的状态与链接；
- 记账清单：`blocker` / `debt` / `nit` 三级，每条带处置与触发条件；
- 未决项：等谁裁、触发条件是什么。

细节仍在五份文档（uat / real-endpoint / mutation / code-review / dsh-review）里，report 只做目录。

### 3.2 播报时点（固定四个）

propose 后、每个切片提交后、三半收尾后、归档前。每次三行：**门禁数字 / 新增记账 / 待你裁决**。

## 4. 独立复核：用编码 harness 的子代理

**为什么换上下文**：见 `devops-loop-rationale.md` §7。

1. **触发**：改规格、不变量（A–F）、安全面的 change 必做；纯文档改动可跳过，但要在报告里写明「跳过，理由……」。
2. **输入只给三样**：change id 与 spec delta 路径、`git diff main...HEAD`、两轴（Standards / Spec）的定义。**不给**实现叙事与结论。
3. **只读**：子代理不得写文件、不得跑会改文件的命令；只能读与跑只读命令。
4. **输出契约**：`verdict`（PASS / PASS WITH FINDINGS / BLOCK）+ `findings`（severity: blocker / major / minor，每条带 `文件:行`）。
5. **记录**：原文贴进 `<change>-code-review.md` 的「子代理裁决」节；主 agent 不得改写结论，只能逐条处置（接受 / 拒绝 + 理由）。
6. **兜底**：harness 没有子代理能力时，退回同上下文自审，并在报告里标注「未隔离」。

**用哪个 harness**：用当前编码环境（WorkBuddy，未来可能是 DSH）自带的子代理能力，**不是** mini 自己的 `subagent` 工具——后者是被测对象，不能既当运动员又当裁判。

## 5. 读量、归档与文档净增

- **读量**：唯一真源是 `AGENTS.md` 的「先读这三样」节，本文不重复。`CURRENT-history.md` 与 `lessons-archive.md` 不读。
- **归并即删**：lessons 合并后，原文移入 `docs/lessons-archive.md`，收件箱只留合并后的条目；收件箱超 15 条先消化再收（规则在 `AGENTS.md`）。
- **流程文档净增 ≤0**：单次提交对 `docs/process/` 的净增行数为 0 或负；要净增必须走 §1.1 第 3 类，由人批准。理由是一次性决定不该长成常驻规则（见 rationale §3）。

## 6. 定时 loop（L0/L1，只报告不改代码）

两条候选，日程要人确认后才建（时区按本机 Asia/Shanghai）：

| 任务 | 频率 | 做什么 | 明确不做 |
|---|---|---|---|
| 每日观察 | 每天 09:00 | 扫活动 change 的未勾 task、最近一次 CI 结论（`gh run list`）、分支落后 `main` 的提交数；输出 10 行摘要 | 不改代码、不提交、不合并 |
| 每周经验 | 每周一 09:30 | 扫 lessons 收件箱条数、Seen ≥3 未晋升的条目、归档体积；输出归并建议 | 不改 AGENTS.md、不删条目 |

**L1 自检的必报指标**：`AGENTS.md` / `CURRENT.md` / 本文件的行数，`docs/process/` 近 10 次提交的增删比，lessons 收件箱条数，`.tmp` 与 `docs/verification` 体积，活动 change 的未勾 task 数。

**分诊不是 propose**：定时任务只做分类与简报，change 的创建与 proposal 必须等人在 grill 对齐里回答后由 agent 起草。分诊结果为空时只输出一行「无新 PR / issue；下一里程碑：X」，不制造噪声。

## 7. 授权与角色隔离

### 7.1 人只决定，agent 自动推进

在**已批准的计划与 change 范围**内，agent 连续推进，不逐步请示：

- **自动做**：一手调研、propose 起草、契约与对齐复核、apply（红→绿切片）、跑四道门禁、两轴审查、三态验收里的真实端点、归档、推 `change/<id>` 分支。
- **人来定**：六类升级点（§1.1）、计划变更、UAT 归属、merge `main`、改 AGENTS/ADR/流程规则。
- **停止条件**：六类升级、merge、UAT、计划外的新需求。除此之外**不问「要不要继续」**，直接做并阶段播报。

### 7.2 角色矩阵（谁做、在哪做）

| 角色 | 谁 | 物理位置 | 隔离方式 |
|---|---|---|---|
| 构建 | agent 主上下文 | 本机工作区 | — |
| 验证 | CI + 测试 + 真实端点 | 独立机器/独立进程 | CI 是另一个 OS 环境，与本地自审天然隔离 |
| 审查 | **harness 子代理**（只读） | 独立上下文 | 只给 spec + diff + 两轴定义，不给实现叙事 |
| 裁决 | 人 | 对话 | 六类升级点 + merge + UAT |

## 8. 明确不做

- 常驻授权 agent 跑 UAT（违反 ADR-0025）；
- 全自动 merge 与自动改 AGENTS.md（人裁是安全边界）；
- 自造 grill / explore 工具（增加维护面，收益与「六问清单」重叠）。
