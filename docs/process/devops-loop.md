# 研发流程的对齐与自动化（提案）

**日期**：2026-11-16。**范围**：本仓库的 change 流程（propose → apply → 两轴 review → 三半验收 → 归档 → 合入）。本文只提议程，不改代码。

## 1. 结论

你的设想**大部分可行**，但有三处口径要改，否则会与现有规则冲突或落不了地：

| 你的设想 | 结论 | 理由 |
|---|---|---|
| 单测 / TDD 红绿 / e2e / 两轴 review 默认 agent 跑 | **可行，已是现状** | 四道门禁与 review 本来就是我跑的 |
| UAT 跑之前提醒你选「你跑 / 我跑」 | **可行，已是现状** | 但 ADR-0025 写的是「人坐终端」，所以我代跑必须**逐 change 授权**，不能变成常驻默认 |
| 重大决策点弹窗 | **可行，需要一份触发清单** | 否则弹窗会随机化：小事弹、大事漏 |
| 别扭 / 未对齐 / 妥协记账 | **可行，已是现状** | 但分散在 code-review 与 dsh-review 两张表里，缺一个出口 |
| 全流程自动化 | **不可全自动** | merge、改 AGENTS.md、UAT 归属三处必须人裁；其余可以自动化 |
| 进入关键阶段前用 grillme / openspec explore 对齐 | **工具不存在，要换替代物** | 实测 `openspec` 只有 init / update / list / view / change / archive / spec；本机也没有 grill 技能 |
| 用 lessons 反推流程简化 | **可行，见第 4 节** | 29 条收件箱可归并成 6 类，其中 3 类能靠流程动作直接规避 |

## 2. 需要新增的四件事

### 2.1 阶段进入对齐单（替代 grill / explore）

在 roadmap 的关键阶段进入前（下一个是 **M14c**，之后 M13、MEM1、E2、H 轨），propose 之前先答六问，答案由人给、agent 不得自答：

1. 这个阶段的**非目标**是什么（明确不做）？
2. 验收判据里，哪一条最可能被「做完但不对」地满足？
3. 有没有需要先补的一手调研？
4. 有没有会动现有规格或不变量（A–F）的改动？
5. 本轮**预授权**的简化/欠账范围是什么？
6. 范围上限：几个切片、什么条件下停？

产出写进 proposal 的「人裁决」小节。六问只问一次，不反复 grill。

### 2.2 决策点弹窗的触发清单

必须弹窗（AskUserQuestion）的六类：

1. **规格级偏差**：与 roadmap 或主规格文字不一致；
2. **不可逆 / 破坏性**：删文件、改日志语义、改 A–F 不变量；
3. **形状变更**：新增事件类型/字段、改 payload；
4. **规则变更**：AGENTS.md、ADR、流程文档；
5. **人的闸**：merge main、UAT 归属、会花钱的批量真实端点；
6. **范围扩张**：超出 proposal 的「非目标」。

约束：**每个检查点最多一次弹窗**，把同类问题合并成一次多选，避免疲劳。

### 2.3 单一出口物：Gate Report

每个 change 一份 `docs/verification/<id>-report.md`，只做索引、不复述细节：

- 四道门禁：命令 + 实测数字（passed / skipped / 覆盖 TOTAL / ruff / mypy）；
- 三半验收：mock / 真实端点 / UAT 各自的状态与链接；
- 记账清单：`blocker` / `debt` / `nit` 三级，每条带处置与触发条件；
- 未决项：等谁裁、触发条件是什么。

细节仍在现有五份文档（uat / real-endpoint / mutation / code-review / dsh-review）里，report 只做目录。

### 2.4 检查点播报（固定四个时点）

propose 后、每个切片提交后、三半收尾后、归档前。每次三行：**门禁数字 / 新增记账 / 待你裁决**。

## 3. 与现有规则的冲突点

- **UAT 代跑**：ADR-0025 要求人坐终端。M14a / M14b 的代跑都有你的明确指示，这是合规的；把它写成「默认我跑」就越界了。建议保留**逐 change 询问**，我在每次 UAT 前弹一次。
- **全自动 merge**：仓库明确规定 merge 与推 main 先征求批准，这是唯一防「未审代码进主干」的闸，不建议自动化。
- **自动改 AGENTS.md**：一进一出必须人裁，否则规则会自己长胖。

## 5. 可简化/合并的

1. **五份验证文档 → 加一份索引**：不合并细节，只减少「找不找得到」的成本。
2. **lessons 收件箱 29 → 6 类**：判据形状 / 环境 / 缓存 / 工具 / 规格 / 审查；合并同类、删已被代码自证的条目。
3. **两轴 review 与对齐复核去重**：对齐复核只列 DSH 十项与偏差，不再重复 proposal/design/spec 三行。
4. **UAT 场次允许 propose 后修改，但表里必须留「为什么改」**：M14b 的 S1 就从 `read` 改成了 `grep`。

## 6. 不建议做的

- 常驻授权 agent 跑 UAT（违反 ADR-0025）；
- 全自动 merge 与自动改 AGENTS.md（人裁是安全边界）；
- 自造 grill / explore 工具（增加维护面，收益与「六问清单」重叠）。

## 7. 落地最小集

1. 本文件进 `docs/process/`；
2. `AGENTS.md` 加一句指针（一进一出：压缩「命令」段里的覆盖率注释）；
3. 下一个 change（M14c）起，按 2.1–2.4 执行，Gate Report 用本文模板。
