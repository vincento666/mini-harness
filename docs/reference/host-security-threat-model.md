# H1 宿主的威胁模型（讨论稿）

**定位**：H1 的 host 把「写操作」从 stdin 挪到本地 HTTP，攻击面变了；这份是给「沙箱要不要提前」用的讨论稿，不是规格。结论先写：**个人本地壳 v1 接受「薄围栏 + loopback + token + 逐次审批」；OS 级文件写拒绝不在 H1，触发条件见 roadmap。**

## 资产

- 工作区里的文件（模型可以 `write` / `edit` / `bash`）。
- 机器上的其它文件与进程（`bash` 以当前用户权限运行）。
- API key（只在环境变量里；日志只记变量名）。
- 会话日志（含用户输入、工具参数、文件内容）。

## 对手与入口

| 对手 | 入口 | 现有控制 | 残余风险 |
|---|---|---|---|
| 被提示注入的模型 | 模型输出里的工具调用 | 审批（ask）、路径边界、CAS、`read-only` 档位 | `bash` 只受档位轴约束（ADR-0008）：`danger-full-access` 或 `workspace-write` 下的 `bash` 可以跑任意命令；薄围栏不防恶意进程 |
| 本机其它网页 | 浏览器向 `127.0.0.1` 发 POST | token、Origin 同源/`null`、CORS 预检 | token 若被同一浏览器的 XSS 读到，可代答审批 |
| 本机其它进程 | 直接读 token env / 日志 | token 不进 argv、不进日志；默认 loopback | 同用户进程可以读环境变量；本地隔离不是安全边界 |
| 恶意/被篡改的壳 | 持有 token，代用户点「批准」 | 审批记录进日志；`auto` 与 `danger-full-access` 要服务器显式允许 | 壳就是用户代理；壳被攻破等于用户被攻破 |
| 远端网络 | `--host 0.0.0.0` | 仍要 token；默认不绑 | 没有 TLS、没有速率限制；公网暴露不是目标 |

## 控制分层

1. **路径边界 + CAS + 审批**（已有）：防「模型不小心」，不防恶意进程（ADR-0003）。
2. **token + Origin + loopback**（H1）：防「别的网页/别的机器随手调用」，不防同用户进程。
3. **进程收容**（M15a，便宜）：job object / kill-on-close / 进程组，防孤儿进程与残留子进程；不防文件写入。
4. **OS 文件写拒绝**（M15b，贵）：ACL / landlock / bwrap，把「写工作区外」变成 OS 拒绝；这是唯一能挡住恶意 `bash` 的一层。
5. **网络隔离**（不在 MVP）：host 只绑 loopback 是它的替身。

## 结论与触发条件

- **H1 可以按现在设计上**：单人、本地、loopback、逐次审批、默认 `ask`；这是「够用的安全」，不是「沙箱」。
- **把 M15a 提前到壳前**，如果：壳要跑无人值守/长任务；或者 `bash` 会在 `workspace-write` 下被大量使用（孤儿进程风险）。
- **把 M15b 提前到壳前**，如果：会跑不可信 skills / MCP / 外部工具；或者 host 绑非 loopback；或者多人使用。
- **不做**：TLS、远程鉴权、网络隔离、容器化——这些不是这个项目的 MVP 目标；真需要时另开 ADR。

## 对 H1 的四条硬要求（已写进 spec，不再加）

1. 默认只绑 `127.0.0.1`；`0.0.0.0` 仍要 token。
2. 除 `/health` 外都要 Bearer token；token 至少 32 字符、不进日志。
3. `danger-full-access` 与 `approval: auto` 都要服务器启动时显式允许。
4. 错误 detail 不回显密钥、Authorization 或完整日志行。
