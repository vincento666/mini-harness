# DSH 对齐检查清单（十项）

**用途**：propose 前的调研与实现后的对齐复核共用的一张镜头，不是新的门禁。每一项写「DSH 怎样 / mini 怎样 / 结论」；结论只用 `aligned / simplified / deferred`，`simplified` 与 `deferred` 是**建议**，由人裁决。

## 1. 形状（Shape）

类型、字段、事件、接口、文件格式、schema 是否同构。

问：双方的数据结构与接口逐字段对得上吗？命名不同但语义相同的，注明「仅命名差异」。

## 2. 机制（Mechanism）

组件、生命周期、时序、所有权：谁在什么时候触发谁。

问：同一件事，DSH 由哪个组件在哪个钩子做？mini 由谁做？触发点与顺序一致吗？

## 3. 语义（Semantics）

默认值、边界、错误词、兼容规则。

问：缺省是什么？非法值怎么处置？错误是结果词还是异常？版本间兼容规则是什么？

## 4. 不变量（Invariants）

必须永远成立的事实，以及它在哪一行代码执行。

问：这条行为违反了 mini 的 A–F 哪一条？执行点在何处？有没有「规格允许、实现绕过」的缝？

## 5. 面（Surfaces）

模型 / 人机 / 日志 / 宿主四个面各看到什么；同一事实的投影是否一致。

问：模型看到的、用户看到的、日志记下的、宿主返回的是同一份事实吗？哪些面故意不同（如审批事件只进日志）？

## 6. 失败与降级（Failure）

缺失、未知、部分失败、取消、恢复、不完整发现。

问：没有配置、未知 id、读不出来、用户取消、进程重启时各是什么结果？会不会静默降级？

## 7. 组合与扩展（Composition）

插件、分层、作用域、遮蔽、扩展点。

问：DSH 靠注册/分层/作用域组合，mini 靠内置还是配置？差异是否影响「多实例/多作用域」时的行为？

## 8. 资源与约束（Bounds）

预算、上限、超时、并发、截断。

问：DSH 的默认上限是多少？mini 的上限在哪定义？超限时是截断、拒绝还是排队？

## 9. 信任与授权（Trust）

审批、沙箱、信任边界、谁可以批准。

问：谁能触发、谁能批准、哪些动作在哪个边界被拒？「能力」与「授权」是否分开？

## 10. 回放与确定性（Replay）

日志 vs 活状态；哪些事实必须进日志。

问：回放时哪些事实从日志取、哪些从磁盘/内存取？技能正文、清单、persona、审批结果各在哪？

## 用法

- **propose**：十项各写一行「DSH / mini / 建议」，把有分歧的项标出来给人裁决；**出处以官方一手资料为准**（上游仓库 README / 包文档 / 源码，引用带 URL 与 commit），`docs/dsh-reference/` 只当索引；
- **对齐复核**：逐条核对实现是否兑现提案与规格，DSH 行只作为其中一类对照；
- 不要求十项都「对齐」；要求**每一项都有结论**，`simplified` 写代价与触发条件，`deferred` 写触发条件。
