# Design

## 边界在哪

三件事今天被一个数承担着，必须拆开：

| 名字 | 公式 | 今天干什么 | 应该干什么 |
|---|---|---|---|
| 触发线 | `floor(min(W × 0.8, W − O − 65536))` | 决定要不要压缩 **且** 决定要不要溢出 | 只决定要不要压缩 |
| 保留预算 | `floor(W × 0.16)` | 决定遮蔽后留多少尾部 | 不变 |
| 压力预算 | `W − O` | 只在摘要请求的裁剪里出现 | **溢出判据** |

`trigger_line < retain_line` 就是死区：压缩无从下手（`shadowed_range` 从最后一条候选起算，`_round_end` 把切点推到整组工具往返之后，落点越过最后一条候选就返回 `None`，`context/budget.py:200-211`），而 `turn_loop.py:841` 用同一个 `reading > line` 判溢出，于是读数在 `(trigger_line, retain_line]` 的装配必死。70000 / 100 那一跑死在 4364 token，窗口允许 69900。

## 决策

**D1 溢出判据 = 压力预算 `W − O`（采用）。** 上下文装不装得下，问的是窗口减去保留额，不是压缩的起跑线。DSH 同一形状：它的压力预算是 `W − O − 65536` 且只在配置解析期用（`TargetPressureConfigError`，`dsh-compaction-basic/lib/index.js:130-131`），运行期的溢出问的是请求是否装得下；mini 版把「装不装得下」显式化为一条估算判据，那这条判据的量纲必须是窗口本身。

- 被否的读法甲：**保留触发线做溢出判据，启动时拒绝 `trigger_line < retain_line` 的配置**。它把 `W < 87890`（默认保留额）这一整段窗口拒掉，而本机端点与本地小模型恰恰常用这个区间；且它修的是「能不能启动」，不是「装得下为什么判成装不下」。
- 被否的读法乙：**保留预算自适应** `min(0.16 W, 压力预算 − 头部 − 摘要余量)`。它改的是压缩的形状而不是判据，且 `0.16` 照抄 DSH 的 `DEFAULT_RETAIN_RATIO`——动它要另立 ADR，且修完死区仍在（只是换个地方撞墙）。

**D2 `pressure_budget(window, reserve)` 住在 `context/budget.py`。** 与 `trigger_line` / `retain_line` 同一模块、同一份常量表，CLI 与 loop 都从这一处读。不加命令行开关：它由已有的两个参数派生，加开关就是第三份可互相矛盾的窗口事实。

**D3 `detail` 给三个数。** 形状 `压缩之后预算读数 <r> 仍超过压力预算 <b>（触发线 <t>）` 与 `无可遮蔽的内容，预算读数 <r> 已超过压力预算 <b>（触发线 <t>）`。理由：死区这件事只有靠这三个数并排才看得出来；今天的 detail 只给触发线，读日志的人无法判断「离窗口还有多远」。整串仍受既有的 200 字符有界规则约束（那条规则在 provider 适配层，这里是回合层，同样单行）。

**D4 摘要请求发不出去不再是溢出。** 今天 `turn_loop.py` 里「一条都装不下」直接通向 `error/context`。改成：不发请求、不写 `compaction/summary`、不写 `error/model`，回到正常装配路径；读数本身超压力预算时才溢出。这样「摘要请求的形状」与「上下文是否装得下」两件事不再互相冒充。

**D5 启动校验不动。** `W − O − 65536 ≤ 0` → 退出码 2 那条比死区严格得多（默认保留额下 `W ≤ 73728` 才触发），保留它；死区不由它管。

## 测试策略

- **seam ①（回合循环）**：三条新判据——死区窗口读数 5933 且无可遮蔽 → 有 `context/assembled` 与不带 `purpose` 的 `model/request`、没有 `error/context`；压缩后读数仍超压力预算 → `error/context` 且 `detail` 含三个数；摘要请求裁到一条都装不下 → 没有 `purpose: compaction` 的 `model/request`、没有 `error/model`、该回合照常装配。
- **seam ⑥（CLI 黑盒）**：`minihns run --window 70000 --reserve 100` 带一份读数落在死区的 fixture → 退出码不是 4、日志里有 `context/assembled`；同一 fixture 配 `--window 60000 --reserve 100`（压力预算 59900 < 读数）→ 退出码 4。
- **seam ④（日志与折叠）**：不动。`shadowed_range` 的切点规则与「不拆散工具往返」原样保留。
- **既有判据的措辞**：`tests/` 里断言「仍超过触发线」的那几条溢出判据要改判据对象（数值随之变），改完必须仍然咬得住——用变异确认，不接受「改完就绿」。
- 词表守卫 `tests/test_vocabulary_reachability.py` 不变：本 change 不新增任何 `code` 或 `stop_reason`。

## 已知代价

- 死区窗口里压缩可能整段都不发生（保留预算比触发线还大），于是小窗口会话的上下文会长到接近 `W − O` 才被拒。这是把「提前撞墙」换成「用到真墙」，代价是单次请求更大、真端点上更容易撞端点自己的上限——真端点那一次由既有的塌成溢出那条路接住（`PROVIDER_CONTEXT_OVERFLOW` → 请求级压缩一次 → 溢出）。
- 「压缩发生了但仍不够」第一次可达，但它需要**摘要本身很大**或**保留尾部很大**才成立；判据用假 provider 造大摘要，真端点那一半能不能撞到取决于模型写多长的摘要，记录时如实写明撞没撞到。
