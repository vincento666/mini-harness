# Design

## Context

`path_key` 是写前必读、CAS 与工作区边界共用的路径身份。它现在是 `realpath`（+ Windows `normcase`）。`realpath` 解析符号链接与 `..`，但**不折叠大小写**；`normcase` 在 POSIX 上是恒等函数。这两件事合起来让「同一个文件、两种写法」在大小写不敏感的 POSIX 文件系统上变成两个键。

## Decisions

**D1 用磁盘上的写法规范化，不按平台猜。** 对路径的每个已存在成分，列出父目录、按 `casefold()` 找磁盘上的名字；找到就用磁盘写法，找不到就停（后面的成分还不存在）。不写探针文件、不读文件系统类型——判据就是这份文件系统自己的行为。

**D2 只规范已存在的前缀。** 新建文件的目标名保持调用给的写法：文件还不存在，没有磁盘写法可言；父目录存在，所以它的前缀仍被规范化。这样「新文件不需要先读」的判据不变。

**D3 每目录一次缓存。** `{casefold(name): name}` 按目录缓存（进程内）。目录里的条目只增不减时映射仍正确；删掉再建同名不同写法的文件是罕见路径，留到真出现时再加失效。

**D4 Windows 保留 `normcase`。** 它同时处理分隔符与大小写，替换它没有收益；规范化只在 POSIX 分支做。

## Risks

- 大目录的每次 `path_key` 是 O(深度 × 目录项)：工作区根条目上万时可能变慢。缓存兜住重复调用；真慢就按目录 `mtime` 失效。
- 两个只在大小写上不同的文件（大小写敏感文件系统）必须仍是两个键：规范化的查找用 `casefold` 精确匹配磁盘写法，找不到就保留原样，所以不会合并。
