# 设计：空白输入不重打提示符

## D1 旗标法，改动最小

输入循环加一个 `prompt_due` 旗标（初值 `True`）：

- 圈顶：`prompt_due` 为真才打提示符，打完置假；
- 空白输入：`continue`（不动旗标——提示符不再出现）；
- 命令只打印不开轮（`/skills`、`/skill`、未知命令）：处理完置真再 `continue`——命令消耗了
  输入行并产出屏幕输出，回到等待状态要说清楚；
- 一轮处理完（内层 while 退出）或命令展开开轮后：置真。

效果：粘贴末尾的空行不再多出一条 `> `；人故意按回车后光标停在空行（上方仍是上一条
提示符），直接输入照样提交。EOF（Ctrl-D）与提示符上的 Ctrl-C 路径不变。

## D2 为什么不用「重打但带换行」或「paste 检测」

- 重打但前置一个换行：只是把 `> >` 变成竖排两条 `> `，粘贴场景下还是多一条。
- paste 检测：终端没有可靠信号（bracketed paste 需要进 raw mode，等于重写输入层）。
- 旗标法 5 行以内、不引入任何新状态到日志——符合「显示行为不动账本」的项目惯例。

## D3 已核实的兼容面

- 现有黑盒测试的 stdout 断言都是「单条输入 + 结尾一条提示符」（`["> 你好", "> "]`），
  旗标法下逐点相同。
- 新增判据：首条前空白 → `["> ", "> 回复一", "> "]`（旧行为是 `> ` 出现两次）。
