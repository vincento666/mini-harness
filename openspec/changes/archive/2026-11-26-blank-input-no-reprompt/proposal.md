# 提案：空白输入不重打提示符

## 为什么

`restore-chat-streaming` 的 UAT 场次 1 复跑（2026-11-25，会话 `b24ba173…`）与场次 3 人跑
（2026-11-26，会话 `065b1909…`）都观察到：提示词粘贴末尾带一个空行（或多按一次回车）时，
stdout 末尾出现相邻两条提示符（人眼看成 `> >`）。已核实（`--no-stream` 对照 + pty 复现）
这是**既有 REPL 行为、与流式无关**：输入循环每圈顶部无条件打一次不带换行的提示符
（`cli/main.py`），空白输入 `continue` 回到圈顶又打一次。人裁（2026-11-26）：另立本 change 修掉。

## 要改什么

`minihns chat` 的输入循环：提示符只在**两种时刻**出现——会话开始后第一次等待输入、以及
处理完一条非空输入（一轮或一条命令）之后。空白输入 MUST NOT 紧接着再打一条提示符。

语义：提示符标记「上次交互之后回到等待状态」这件事；空白输入没有产生任何交互，
提示符保持原状（光标已在下一行，输入照常可提交）。

## 不做什么

- **不改日志与退出码**：提示符本来就不进事件日志；空白输入不写记录、不开轮的规则不变
  （`chat-repl` 既有 Requirement）。
- **不改 stdout 投影**：正文、`[answer]`、诊断行的规则全部不动；`--no-stream` 基线逐点相同
  的要求不适用（这是 REPL 显示行为，规格此前未对提示符计数设规），但正文投影不受影响。
- **不做 paste 检测**：终端没有可靠的粘贴信号；本 change 只按「空白输入」判定。
