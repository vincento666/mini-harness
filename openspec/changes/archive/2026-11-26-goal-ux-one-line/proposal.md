# 提案：一句话任务的 UX——把分轮流程从用户提示词移进政策段与工具描述

## Why

UAT 与真端点实验反复证明：**当前「多轮完成长任务」依赖用户写出显式的流程提示词**（「先 create_goal，max_rounds 设为 3；建目标的本轮不要写任何正文；每轮写完用 todo 记进度；最后 update_goal complete」）。一般用户只会给一句话（「写个贪吃蛇」「分三轮讲个故事」），不会这样表达。

证据（2026-11-26）：

- UAT 场次 3 用带全部流程约束的提示词跑，模型**仍然**把「第一段」写进建目标的人类轮（会话 `c1b33863…` 的 s1 正文 137 字符含 `**第一段**`），目标轮 1 又写一遍 → 内容重复。说明这类约束靠提示词不可靠。
- `goal-round-pacing` 已落地 L3（`MAX_STEPS` 是轮边界）与 L0（受保护政策段 v2），但 v2 只说明「建目标后想分轮就结束本轮」，**没有**说明「建目标那轮只做计划、不产出内容」「每轮只推进一块」——模型没有依据自行分轮。
- `create_goal` 的工具描述只有一句「创建一个目标并开始自动续跑；已有未完成目标时拒绝（单目标）」，没有「何时建」「建完就停」的条件句。

## What Changes

1. **受保护政策段升到 v3**（`GOAL_POLICY_VERSIONS` 新增 `"v3"`，v1/v2 原文保留给旧日志重算；`GOAL_POLICY_VERSION = "v3"`）。v3 在 v2 基础上补三条：
   - 用户给的任务需要多步或多轮完成时（哪怕只有一句话），**第一步就建目标**，`objective` 复述用户目标；不要等用户吩咐流程。
   - **建目标的那一轮只做计划**（todo 列出分轮步骤）就结束，正式内容从目标轮 1 开始。
   - **每个目标轮只推进一块可验收的工作**，写完就停在轮边界，不要在一轮里把整个任务干完；每轮收尾用 `todo` 记一句进度。简单问答或一步能做完的事**不要**建目标。
2. **`create_goal` 工具描述改成条件句**：说明何时该用（需要多步/多轮，哪怕用户只说一句话）、建完结束本轮且只做计划、正式内容从目标轮 1 开始。
3. 规格同步：`context-projection`（政策版本与必含句子）、`goal`（工具描述必须写成条件句）。

## 不做什么

- **不做「自动建目标」的黑箱判定**：仍由模型决定是否建目标；政策只给它判断依据（多步/多轮才建，简单问答不建），避免「你好」也建目标的过度反应。
- 不做「建目标后硬停」的机制（L2 已被 `goal-round-pacing` 人裁否掉）：建目标那轮是否写内容仍由政策约束模型，而非引擎强制。
- 不改 `[轮] n/cap` 的计数与显示（`round-label-prompt-alignment` 已定案）。

## Impact

- 所有新会话的政策段从 v2 变 v3（含 `run` / `serve` / `chat`）；旧日志仍按 v1/v2 重算。
- 验收方式：用**一句话提示词**跑真端点（不加任何流程说明），看是否自动建目标、每轮一块、轮边界停下、完成后 `update_goal complete`。
