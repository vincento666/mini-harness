# 设计：一句话任务的分轮流程落在哪一层

## D1 三层候选与取舍

| 层 | 作用范围 | 是否可被用户覆盖 | 结论 |
|---|---|---|---|
| 用户提示词（当前跑法） | 单场 | 要用户自己写 | **否**——一般用户不会写，且场次 3 证明模型不守 |
| 受保护政策段 | 每个会话，常驻 | 否（`--append-system-prompt` 只能追加） | **采用**（v3） |
| `create_goal` 工具描述 | 模型读工具表时 | 否 | **采用**（条件句） |
| 引擎硬约束（建目标后禁止写正文） | 每个会话 | 否 | 不做（L2 已否；且会误伤「建目标 + 当轮就问澄清」的合理场景） |

## D2 v3 的三条新句子

1. 「用户给的任务需要多步或多轮完成时（哪怕只有一句话），第一步就建目标，`objective` 复述用户目标」——解决「用户不写流程」。
2. 「建目标的那一轮只做计划就结束，正式内容从目标轮 1 开始」——解决「第一段写进人类轮」导致的 `[轮]` 错位与内容重复（场次 3 残留）。
3. 「每个目标轮只推进一块可验收的工作，写完停在轮边界；每轮用 todo 记一句进度；简单问答不要建目标」——解决「一轮把活干完」与停滞闸门误杀，并给「何时不建目标」一个反面条件。

## D3 为什么保留 v1/v2

政策文本按版本冻结（`context-projection` 规格）：`context/assembled` 存了完整 messages，就地改写会让按旧版本记录的日志重算不一致。v1/v2 原文留在表里，`GOAL_POLICY_VERSION` 指到 v3。

## D4 验收口径（关键）

用**一句话提示词**跑真端点，不加任何流程说明：

- 编码类：「写个命令行小工具 fizz.py，打印 1 到 30 的 FizzBuzz」→ 期望：模型自己 `create_goal`、建目标那轮只计划、之后每轮一块（骨架/实现/测试/验证）、完成才 `complete`。
- 文本类：「分三轮讲一个故事」→ 期望：不建目标也能正常答（单轮），或建目标后每轮一段（两者都可接受，不得出现重复段落）。

通过条件：至少 3 场不同任务，全部在**无流程提示词**下出现「建目标 → 分轮推进 → 完成或明确未完成」，且没有出现「一轮干完整个任务」或「第一段写进人类轮」。
