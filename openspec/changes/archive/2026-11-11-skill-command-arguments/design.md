# Design

## Decisions

**D1 两种形态。** `/<技能名>`（无指令）保持「打印正文、不开段」——它是查看；`/<技能名> <指令>` 是「用技能做事」——展开成消息、开段。`/skill <名字>` 仍只加载正文，不接受指令（要带指令就用 `/<技能名> 指令`）。

**D2 消息形状。** `user/message` 的 content = 技能 XML 三段 + 一个空行 + 指令原文。正文落 `user/message`，所以回放稳定；XML 与 `skill` 工具的结果同形，模型不需要学两套。

**D3 host 复用投递路径。** 先写 `command/run` + `command/done`，再调用 `submit_message`（空闲起段、忙时排队、队满 409）。返回 202 与 `{queued, segment_id, cursor}`；不做第二套状态机。

**D4 内置优先不变。** `/<内置名> 指令` 仍是内置命令；要带指令用技能，只有技能名可以展开。
